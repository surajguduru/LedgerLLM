# Deployment runbook

Production is one Docker container on Render (free web service) plus a Neon Postgres database (free tier).
Everything is configured through environment variables; nothing is baked into the image.

## First deployment

1. **Database (Neon).** Create a project at <https://console.neon.tech>, region close to the Render region.
   Copy the connection string and change the scheme for psycopg 3:
   `postgresql+psycopg://<user>:<password>@<host>/<db>?sslmode=require`.
   Neon is used instead of Render's own Postgres because Render's free database expires after 30 days.
2. **Web service (Render).** New → Blueprint → select this repository. Render reads `render.yaml`. Fill in:
   - `DATABASE_URL` — the Neon string from step 1
   - `LLM_API_KEY` — the Gemini key (<https://aistudio.google.com/apikey>)

   `ADMIN_TOKEN` is generated by Render; copy it from the service's Environment tab. The health check is
   `/healthz`. Tables are created on first start (`create_all`).
3. **Seed tenants** from a laptop against the production database:
   ```bash
   DATABASE_URL='<neon string>' .venv/bin/python -m scripts.seed
   ```
   This prints the API keys once and writes them to `.seed_keys.json` (gitignored). Share them out of band;
   never commit them.
4. **Smoke test:** `scripts/demo.sh https://<service>.onrender.com`.

## Rolling out a change

| Change | How it ships | How it rolls back |
|---|---|---|
| Code | PR → CI (lint, tests on SQLite and Postgres, red-team gate, summarization gate) → merge to `main` → Render auto-deploys | Render → Deploys → *Redeploy* the previous build |
| Prompt | add `prompts/summarize_vN.yaml`, merge, then set `SUMMARIZE_PROMPT_VERSION=summarize_vN` | set the variable back (Render restarts the service; no build) |
| Guardrail layer | deploy with `GUARDRAILS_MODE=shadow`, read the shadow report, then `enforce` | set `shadow` or `off` |
| Response cache | on by default; TTL per plan in `config/plans.yaml` | `RESPONSE_CACHE_ENABLED=false` |
| Schema | additive only (new tables and nullable columns), created on start | old code ignores the new columns |

## Operating notes

- **Cold starts.** The free web service sleeps after 15 minutes without traffic; the first request then waits
  for the container to boot. Send a request to `/healthz` before measuring latency or giving a demo.
- **Connections.** The engine keeps at most 10 connections (`pool_size=5`, `max_overflow=5`) and recycles them
  every 5 minutes, which suits Neon's connection cap and idle suspension.
- **Fallback host.** Hugging Face Spaces (Docker SDK) runs the same image; the container honours `PORT`.
- **Database down.** The pipeline fails closed: no budget reservation means no model call, and the client gets 500.
